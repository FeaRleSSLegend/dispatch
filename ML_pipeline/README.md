# Dispatch — ML Pipeline

The classification engine behind Dispatch. Given a free-text incident report,
it predicts a category and severity, extracts technical entities, and redacts
personal information. The backend calls `process_report()` on every
submitted report and on-demand from the analyze page.

Classifies free-text incident reports into a category and severity, extracts
entities, and redacts PII.

## What it produces

`process_report(text)` returns:

```python
{
  "category": "phishing",           # phishing | account_takeover | malware | data_leak | suspicious_activity
  "severity": "high",               # low | medium | high
  "score": 53.3,                    # category confidence, 0-100
  "entities": {
    "ips": [...],
    "urls": [...],
    "account_refs": [...],
    "organizations": [...],
    "time_references": [...]
  },
  "cleaned_text": "...",            # PII-redacted version of the input
  "routed_to": "IT Security"
}
```

## Models

Three `.joblib` files in `models/`:

- `tfidf_vectorizer.joblib` — TF-IDF vectorizer (word unigrams + bigrams)
- `type_classifier.joblib` — LogisticRegression, predicts category
- `severity_classifier.joblib` — LogisticRegression, predicts severity

Loaded once at import time. Retraining overwrites them.

## Layout

```
src/
├── pipeline.py            process_report() — the entry point
├── preprocess.py          text cleaning + vectorizer
├── extract_entities.py    regex + spaCy NER
├── redact_pii.py          PII redaction (names, phones, emails, NINs)
├── dedup.py               find_duplicates() — cosine similarity in a time window
├── train.py               trains and saves the models
└── evaluate.py            scores against the held-out test set
data/
├── incident_reports_dataset.csv    training data
├── held_out_test_set.csv           generated by train.py
└── misclassified_reports.csv       generated by evaluate.py
```

## Setup

```bash
python3 -m venv venv
source venv/bin/activate
pip install scikit-learn spacy pandas numpy joblib
python -m spacy download en_core_web_sm
```

## Train

```bash
cd src
python train.py
```

Reads `../data/incident_reports_dataset.csv`, splits 80/20 stratified on
category, fits both classifiers, writes the `.joblib` files, and saves the
held-out rows to `../data/held_out_test_set.csv`.

## Evaluate

```bash
cd src
python evaluate.py
```

Scores the saved models against the held-out set. Writes misclassified rows
to `../data/misclassified_reports.csv`.

## Notes

- `pipeline.py` resolves `MODELS_DIR` relative to its own file, not the CWD.
  The backend can import it from anywhere.
- Dedup is batch-only (`find_duplicates()` takes a list of reports). The API
  does not currently use it.
- Model accuracy and calibration are not strong. Category accuracy is ~74%
  on held-out data; severity ~60%. Confident predictions cluster around
  30-55%. Treat the output as a suggestion, not ground truth.
